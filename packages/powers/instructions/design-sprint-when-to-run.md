# Decide when to run a design sprint

Run a sprint for a high-stakes decision, when normal build-and-test is too slow, debate is stuck, multiple solutions compete, a new product/feature/major redesign is under consideration, or de-risking is needed before investment. Do not run one when the problem and solution are obvious and execution is all that is needed, the team is not bought in, or the Decider cannot attend the full week.

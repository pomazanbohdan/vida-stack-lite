# Append only in supplement mode
Supplement mode must NEVER modify, reorder, or rephrase any existing line in the file. Only append new ## sections that are completely absent.
Append only missing sections to a hand-written doc. NEVER modify existing content.
Extract all `## ` headings from existing_content.

# Mark the claim you could not verify instead of asserting it
Place `<!-- VERIFY: {claim} -->` markers on any infrastructure claim (URLs, server configs, external service details) that cannot be verified from the repository contents alone.
Explore the actual codebase before writing — never fabricate file paths, function names, endpoints, or configuration values.

# Say there is no standalone run mode instead of inventing a run step
Not every target can be run locally. When a project or package has no runnable entry point (event-triggered handlers with no CLI or HTTP surface) or cannot start from repository contents alone (required config comes from a secrets manager or deploy-time environment), do NOT write a literal run step or fabricated usage output.
Fall back in this order: the test command, then the build command, then an explicit "no standalone run mode" statement.
Targets with a normal entry point (`scripts.start`, a CLI bin, `go run`, `docker compose up`) keep the normal run step.

# Use a targeted edit, not a whole-file write, when you fix a claim
NEVER use the Write tool on an existing file in fix mode. Write replaces the entire file with whatever you provide — any content not in your context window is permanently destroyed.
Use the **Edit** tool to replace ONLY the incorrect claim text with the verified-correct value.
Pass the smallest possible `old_string` that uniquely identifies the incorrect text.
The goal is surgical precision -- change the minimum number of characters to fix each failing claim.

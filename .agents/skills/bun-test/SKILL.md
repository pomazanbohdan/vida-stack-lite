# Bun Test development

Use the smallest contract-backed check that resolves the current uncertainty.
Keep behavior, timing and numerical qualification as separate evidence. This
skill gives the working method. The package's [testing guide](../../../packages/agent/TESTING.md)
owns commands, timeouts, evidence gates and accepted policy. Its
[regression contract reference](../../../packages/agent/docs/research/test-regression-contracts.md)
owns detailed scenario-specific requirements. Read both before changing an
affected owner.

For Initial Source binding-checkpoint paths, reuse the queued TaskSource fixture
named in TESTING's shared-helper contract. An issued same-work action remains
UNKNOWN and correctly blocks writer resolution; queueing behind a real peer
can create the checkpoint without an own action. Preserve the peer's issued
action and use the original configured writer verifier for the positive path.
Do not manufacture a checkpoint or settle UNKNOWN merely to reach a counter.

For TaskSource history after corrective execution, use the native terminal
attempts as the witness oracle. First advance Work through an actual supported
CAS when testing a later history reader: corrupting the exact successor version
correctly trips its checksum before the intended prefix guard. Retain that
failed premise. Compare every table after exact restoration, and keep issued
proposals unexecuted and retained. The v2 history contract and bounds belong
to TESTING and the system specification.

For historical terminal capture, preserve the original issued item's null
observation and exact receipt-bound Journal. Seed component prerequisites before
persistence and capture; do not rewrite the captured Journal into a completed
observation. Check that continuation retains the original only in prior_journal,
preserves the completed prefix and installs one unissued review. Include foreign
issue, activation and sibling refusals plus exact retry and restored receipt
corruption. A trusted Host component fixture is not public CLI qualification;
trace whether a cited CLI case is positive or denial-only before reusing it.
For a native multi-assignment research wave, configure the assignments before
admission, activate the whole wave before exposure, and retain each actual
normalization and artifact admission. Use distinct action-bound tool-call refs
and topics. A captured pending continuation needs both exact admitted
predecessors. Test changed record bytes before and during authorization, missing
repository binding, detached refs, retained exposure and pure history reads.
Do not replace that positive path with a component fixture containing only refs.
For Host package-transition tests, reuse the single-resource beforeimage fixture.
It supplies an actual captured old snapshot as controlled input and restores the
snapshot spy before the current-package frontier and recovery checks. Unchanged
resources keep their verified reader. Do not replace package-root guards, install
the copied resource, insert qualified history rows, or claim native qualification.
Its scoped callback receives an idempotent restore operation for a case that
must finish old-bound native setup before opening the current-package reader.
Configured normal endpoints require distinct old/current runtime digests; use
the captured old resource and current snapshot, not equal digest placeholders.
Keep the prior resource reader bound on the old endpoint verifier and preserve
the report recovery's exact frontier/runtime digest join.

For uncovered-function navigation, reuse the report's retained `istanbul_key`
and `body_location` when present and matched to its bound Source map. The
existing exact-geometry join owns them. Do not reconstruct IDs from map order,
function names or a fresh index. Historical reports may lack this optional
navigation data; preserve that GAP and their original bytes.
For an objectively untestable path, use TESTING's objective-skip disposition.
Bind the exact report counter, prerequisite and independent review in WORK.
Keep measured counts and numeric outcome unchanged; an unreviewed search gap,
ordinary failure or timeout is not a skip. Queue progression is separate from
exact coverage, frozen-budget or mutation acceptance.
Reuse exact zero-count branch-arm lists as well as missing function IDs. Check
their count against the same report's branch deficit and preserve explicit
implicit-if range labels. Select causal cases from actual gaps; additional
denial assertions alone need not increase Istanbul's visited-operand counts.
Check the actual Source expression at each retained zero-arm location; a nearby
repeated predicate or shared function owner does not identify that counter.
Quote that expression in the review before proposing a producer or disposition.
For Istanbul `binary-expr`, an arm counts evaluation of its mapped operand,
not that operand's truth value. A missing right operand in `left && right`
requires a truthy `left`; `right` may be false. In `left || right`, a falsy
`left` reaches the right operand. Check the retained location and operator
before declaring a required pair of states impossible.
For a complete native no-write oracle and observers inside production catch
boundaries, use [TESTING's contour rules](../../../packages/agent/TESTING.md#rolling-contour-repair-cycle).
Capture observer calls in an owned counter before restoring a Bun spy; its call
history after `mockRestore` is not a durable observation. Complete real synthesis
prerequisites before choosing a later readonly frontier for a negative writer
request. Check the actual admitted packet after a native transition, outside
the verifier's catch. A generic approval denial alone cannot identify its guard.
Record actual native reads before asserting denial; an orphan coordination
ticket can reject a missing Work before the intended resolver guard. In a
test-owned Host-disappearance fault, remove the exact Work/coordination pair
atomically and restore both exact rows. Keep the native reader's guard intact.
For a real peer-admission race, follow TESTING's post-transition snapshot rule.
The approval caller reads lineage before the resolver; arming there tests the
supplied-snapshot boundary. Arming after the resolver's first native Journal
read targets its later policy reread. Keep both actual peers and obtain one
fresh successful reservation after the refusals. Do not infer either boundary
from a raw total count of Host or lineage reads.
An active same-work TaskSource proposal creates a native binding checkpoint,
but its issued UNKNOWN action still blocks Source-root resolution. Preserve and
test that refusal; do not synthesize a no-effect report to reach later policy.
Use the supported queued-resource producer, which has no issued own action, for
the later checkpoint composition. A direct checkpoint read is not private digest
coverage. Keep that claim pending until the complete report records the arm.
Before extending a code-workflow fixture, inspect the loader's complete stage
and profile predicates. Its pre-development validation permits only the exact
configured prewriter. For an observed/pending peer wave, select the existing
high-risk two-prewriter route before admission and report a typed preparation
through its maintained helper. `source_write: false` alone does not establish
the UNKNOWN-readonly predicate: a validator policy containing `test.read` is
outside that predicate. Narrow the fresh fixture's profile to the actual
read-only/no-egress policy; do not weaken the product guard. Serialize fresh
transformed YAML without duplicate-object aliases, which the loader forbids.
For unchanged callable bodies in a changed file, reuse retained report geometry
only after an exact body/relative-location comparison and current transitive
prerequisite review; this navigation proof never changes measured counts.
An empty missing-function group does not mean there are no uncovered statements
or branch arms. Read each exact counter and its own retained gap list before
classifying the contour or asking for another scan.
For the report-only gap map, `rows` contains missing functions; use `branch_gaps`
and `statement_gaps` for their own counters. Read the map file, not its producer's
stdout summary. Pass an explicit
output path to the existing mapper; if it already wrote the current map before
an observer fails, recover that file instead of rerunning the report producer.
Start an exact-counter disposition review after the current complete report has
refreshed that map. Earlier producer
research remains provisional. Resolve the report path from the map's `report`
or the stage's `publication.json`; do not retype long execution-image identifiers
or infer staleness from an optional absent commit field.
Use the existing gap mapper and generated Markdown projection for bounded reads.
For terminal outcomes select explicit scalar fields; never dump a raw report or
every dictionary key. Coverage/function arrays and digest catalogs can expand to
megabytes even when top-level arrays were filtered. Truncation limits tool output,
not the cost of producing it; inspect a bounded shape before an unknown schema.
For process cleanup, prove detached-descendant termination and reaping separately
from owned process-group closure. A zombie has no useful command line; a native
test can assign its own unique kernel `/proc/self/comm`, confirm it before exit,
then check that name after completion. Bun's process.title is not that kernel
comm. Keep namespace-init and outer-launcher reapers under their existing owner;
do not signal old PID-1 zombies or alter original custody receipts.
Before removing a guard as dominated, verify the exact schema's minimum list
length and the validator's empty-list semantics. Reference checks using `every`
can pass an empty list without proving that a later lookup has a seed. Preserve
the guard and exercise the public refusal when the preceding contract allows it.
Distinguish validated stored state from a public builder's unvalidated DTO input.
Keep malformed negative DTOs outside persistence and authority; require the
public refusal and exact native beforeimages, not an accepted fabricated state.
For untyped SDK runtime refusal, an explicitly malformed raw DTO can use the
existing bound-method `Reflect.apply` convention. Keep nonnull TypeScript API
contracts intact, discard the result, and prove the verifier was never called,
native rows/schema stayed unchanged and the transaction closed. Do not cast the
DTO into valid input or use a snapshot helper that needs an absent Journal table.
An omitted compatibility/history field in a corrupted current receipt can prove
a fail-closed reader path. Preserve exact guarded restoration and label that
negative evidence honestly; it does not establish genuine legacy acceptance.
For UNKNOWN recovery, check the original and effective report's own integrity
and their status relation. An outer payload digest or a valid effective report
alone does not prove that both retained reports are consistent.
After a configuration continuation, use the Journal owner bound to that current
configuration. A ledger facade retained from preparation still checks its old
config and can reject before the intended test boundary. Reuse the current facade
already needed by the subsequent positive control.
For a configuration-race refusal, keep the old facade's freshness check. Compare
the exact native Journal rows when the deliberate configuration change makes
that facade reject, and assert its rejection separately. A completed native
admitted-context read proves more than observing its first Host lookup.
For an identity-transfer regression, use a fresh live preparation whose Source
still matches its accepted scope. Initial-source continuation retains protected
original scope and intake; those bytes cannot simply be reused for a fresh
identity after Source changes. Exclusive ownership rules out simultaneous
claims, but does not rule out a supported suspension followed by fresh admission.
After a genuine maintenance acquire/release before fixture admission, reopen the
configured ledger before creating Work or its bridge. Its opened generation is
immutable; releasing the fence does not refresh an existing handle. Keep this
setup optional so ordinary fixtures do not add an await or reopen. Preserve the
failed stale-generation fixture and exercise the original positive path afterward.
For continuation-context coverage, keep the retained engine's original context
and project successor requests with the actual evolved Source scope. Assert that
the new context derives a different run identity before opening the real bridge;
an unchanged scope can short-circuit the compatibility route under test.
At an awaited verifier-to-transaction boundary, a deliberate exact-row deletion
can test the later native recheck. Restore only the captured absent key with
guarded insertion and compare every original column before the success control.
Before composing continuation fixtures, check actual lease resources and
retained engine context, not just compatible receipt types. Code-only adoption
requires sole execution-only ownership; a configured frontier may hold file
claims. An initial-source successor may preserve an engine's original input
context. Do not weaken those guards to make a fixture composition pass.
For real post-report engine progression, use the actual package endpoint and keep
the bridge open. A Host-only readonly preparation is not an accepted Journal item;
retain that history proof in its existing case and keep the separate next-wave
case bound to real completed Journal observations. Omit unrelated peer setup only
from that independent case, preserving the peer controls in their original cases.
A checksummed stored receipt can reach a history operand before its structural
validator. Trace actual evaluation order before proposing an objective skip;
exercise a refused, exact-CAS-restored corrupted row when that path is reachable.
Do not assume a receipt validator checks lifecycle authority merely because it
checks lineage. A refused historical-reference probe may need the original and
successor arrays changed equally and their existing Work/request digests rebound.
Require the later authority refusal, exact Host/Journal/DDL beforeimages and
guarded receipt restoration. Reuse the two-table typed fixture owner for this
corruption and the delivered-Journal probe; never accept the altered history.
For recovery history, a real prior readonly attempt alone does not bypass a
transaction-local projection shortcut. Use the supported changed runtime proof
and assert both preserved history and the changed binding; distinguish the
successful read from a tamper refusal rejected earlier.
For stale-owner reader tests, suspend through the actual public producer and
restore only the observed changed fixture rows with exact post-suspension CAS.
Check the producer's full predicate: an unissued current item does not mean its
completed history is empty. Preserve the original positive path after restoration.
A callback that removes lineage may be rejected by intermediate progress/admission
validation before a later reread. Assert the observed refusal and rollback, and
trace that earlier guard before claiming either a branch visit or an objective skip.
For a collector's false arm, inspect nonmatching entries as well as duplicates.
A valid public append can create an old-binding artifact that a proposed successor
must reject later. Use real copied artifact bytes and its public Host CAS, require
the refused transaction to preserve its beforeimages, then restore only exact
changed fixture rows before the original success control. This is refusal
coverage, never an accepted manufactured continuation or an objective skip.
For malformed sibling projection controls, reuse parser-valid research fixture
fields, register its root with the enclosing failure-retention owner, and keep
invalid history inside a refused or explicitly fault-aborted transaction. Compare
native Host/Journal/DDL beforeimages and restore the exact injected row before
the original success control. A source-derived visit remains a hypothesis until
the complete contour report records it.
Register a constructor's root immediately after allocation, before its first
write, through the fixture's existing onRoot convention. An expected setup-error
control uses the ordinary case owner: retain on real case failure, then permit
normal cleanup on PASS. Forcing the retained-root list from a passing control can
unnecessarily retain the entire enclosing installed fixture. Keep original failed
attempts and their custody unchanged when correcting this test behavior.
Before declaring a fixture absent, inspect every test path in the contour's
existing selection. A missing direct call in one selected file is not a contour
prerequisite GAP; another selected file may own the real producer and fixture.
Trace the actual report dispatcher rather than infer it from a stage's role.
A synthesis item with a real Host reservation can enter the completed Source
report boundary. Conversely, a reconciled unissued action can resume through its
ordinary unreserved report and leave the exact ticket fence for a later writer.
Prove that later writer's different slot, null predecessor and exact retained
retry lease through the public producer. A released ticket observed after the
report does not show which ticket was current when that report was accepted.
For a pre-report refusal, stop an opt-in fixture at that verified boundary instead
of preparing unrelated later workflow stages; preserve normal failure retention.
For completed-report retry assertions, the failed-final fixture's existing
`verifyNoEffectReport` callback still precedes the Ledger report. Submit the actual
observation through that public report owner before checking ownership release;
then assert exact replay without continuing unrelated validation phases. Return
the case's completion predicate when cleanup must retain a root after its deadline.
The helper evaluates it after bridge/database closure. Check that the returned
predicate is consumed; an early body success must not discard a late failed root.
For a composed Host lineage read, reuse its atomic view and captured versions.
Do not rebuild the join from separate readers or serialize already validated
large receipts under a smaller generic byte limit. A test-only policy adapter
on the same DB must preserve the original store's workflow verifier; keep it as
a separate view when it only prepares/issues TaskSource metadata. Follow
TESTING's native resource-history rollback and checkpoint controls.
For a stored-history refusal beyond the generic Work validator, start with real
different-slot attempts and change only the intended fixture row. Preserve the
actual report reservation and observation. Keep corrupted-input evidence distinct
from a genuine producer; do not add invented accepted attempts to reach a guard.
Reuse the row-corruption owner for original, denied and restored Host/Journal
beforeimages, revision/digest CAS restoration and preservation of body/cleanup
errors. After restoration, accept the unchanged original report as the positive
control. Keep retry evidence paths exclusive across all slots in the same fixture.
After moving proof setup between cases, check the next report for lost closure
and branch visits even when every case passes. Preserve required queued/active
states in compatible existing cases and keep their original per-case bounds.
Distinguish an absent table from an absent positive-attempt row in a populated
table. Prefer an extra read in the existing real producer fixture, preserving
its row oracle, over another setup or a fabricated empty success table.
Check which tables a shared snapshot helper requires before choosing it for an
absent-storage refusal. Reuse prepared Host-row and catalog queries when no
Journal table exists; do not create storage merely to satisfy the test oracle.
Before adding Host unit history to a composite, check later Journal acceptance
requirements. A completed Host readonly result is not an accepted Journal item;
keep that probe in a compatible existing case rather than weaken recovery.
Use descriptive string labels for parameterized proof cases and check the
expanded native names. Boolean inputs with `%s` can retain identical literal
labels on the selected Bun; distinct assertions alone do not give distinct names.
Bind every alternative of a grouped test-name filter to its exact declaration;
several passing alternatives can otherwise hide one absent alias.

## Load the current owners

Resolve the repository root. Read `AGENTS.md` and `AGENT.sidecar.md`, then the
[self-development protocol](../../../packages/agent/instructions/development-lifecycle.md#self-development-protocol),
[TESTING.md](../../../packages/agent/TESTING.md), and the affected package
scripts. Read only the linked regression sections relevant to the change. These
owners define scope, authorization, custody and commands; this skill does not
replace them.

Anchor direct focused invocations to the package root as well as the test path.
The root checkout's Bun invocation can omit the package configuration, preloads
and seed. Preserve that observation, then use the declared package profile for
the affected check; do not interpret the profile change as a code speedup.

Check the executing Bun against `.bun-version`. Availability of a newer release
is not qualification. Bun executing TypeScript does not establish strict
typecheck success. Runtime and declaration versions are independent. Use the
selected Bun pin and manifest/lock declarations without embedding the current
runtime version in tests. Keep build and install free of test suites.

For scoped strict checks, use tooling/quality-current.ts's createCompilerProject.
It resolves explicit package-relative entries against packageRoot and preserves
absolute entries, so a generated config in another directory keeps the same
compiler roots. Keep inherited strict options and ambient declarations intact.

For full coverage SDK readiness, use the maintained coverage alias and its
internal readiness owner. Reuse the existing capture's complete SDK input
projection for both cache validation and a necessary local test-input build.
Check every declared output and preserve prior/failed publication roots. Test
bodies never compile their own SDK, and formed images never refresh artifacts.
If artifact validation already owns copied buffers, reuse those private bytes
in its returned map instead of copying each output again. Verify output order
and mutate every returned output/receipt in the ownership control to prove the
caller's original bytes remain unchanged.
Local formation runs no suite and establishes no product delivery or Runtime
acceptance. Preserve the installed-dependency custody limit and strict freshness.
For a focused selection, reuse `sdkFormationToolInputPaths` and the declared tests
to determine SDK dependency. Reuse selectedTestsRequireSdkArtifacts: public
run/controller fixtures can require the SDK export-completeness fence even when
they execute Source directly. Follow the actual guard and positive caller path;
a negative case that exits before that guard is not an SDK consumer by import alone.
Native Host/corrective helpers can reach that same guard. Add their selected test
file to the maintained selector and check the SDK capture projection, including
nested test paths; do not infer Source-only execution from its directory.
A selection without SDK-dependent tests does not capture dist or need separate
artifact preparation. Keep automatic internal
formation and all freshness checks for selections that actually consume the SDK.
The native batch pilot uses the v4 complete-partition descriptor described in
TESTING. Preserve registry execution order while sorting only capture metadata;
never relabel focused input as v3 full-current evidence. A pre-baseline SDK error
in a non-SDK contour needs its capture scope checked before another SDK build.
If no runner receipt exists, read the original launcher result and stderr before
changing tests. Standalone captures traverse declared executable tools through
the same bounded closure owner; do not rely on an unrelated test importing their
dependencies or repair a sealed sandbox by copying live files into it.

After a focused producer terminates, use the maintained contour progress CLI's
`--coverage-run <focused.json>` to import its matching operation outcome and
print concise metrics in one step. Do not dump complete instrumented maps just
to read totals. Preserve the actual BLOCKED/FAIL/UNKNOWN status independently
of coverage. Reuse `campaignProcessState` in session launchers and separately
check unchanged boot identity; do not duplicate a weaker custody/log predicate.
For representation-only snapshot maintenance, use TESTING's existing
`repackContourProgressSnapshot` owner instead of rescanning/importing observations.
Keep every attempt and its proof bindings, legacy readers, the32MiB bound and
atomic publication. Verify complete expanded equality; compaction grants no
new metric or currentness. Read the compact Markdown view for navigation rather
than dumping a cumulative JSON snapshot into the agent context.
Reserve a fresh exclusive diagnostic log for each attempt under TESTING's
retention rule; a successful retry must not overwrite a prior failure.
Give reviewers absolute evidence paths anchored to the repository, not a fixture's
working directory. Missing evidence at a mistaken relative path is not a reason
to repeat the producer; resolve its retained locator and distinguish static review
from independently inspected runtime evidence.
For a new or modified case using shared fixture teardown, set its existing
failure-retention marker before the first awaited setup and clear it only on
success. Capturing an execution image cannot preserve files the case deletes.
Read the native exit receipt separately from the outer tool outcome. Diagnose a
disagreement with an inert control before another expensive invocation, following
TESTING's capture rule. Preserve both outcomes and require full producer custody
for numeric qualification.
After an orchestration transport error, inspect every earlier call's retained
logs and process state before retry. A later call's launch rejection does not
prove that an earlier call never started. Partial test rows without a terminal
summary remain incomplete; preserve their original logs and fixtures.
Separate artifact downloads from process inspection. For owner checks, list
PID, parent PID, state and command names instead of full caller argv, which can
echo a temporary signed transport URL. Keep those URLs out of retained summaries.
During the owner's sequential exact F/L/S/B phase, work on one contour only and
defer frozen CRAP and mutation producers. Preserve their existing gaps and
evidence; a coverage milestone is not complete-triple closure. Do not launch CRAP
merely to reconfirm a known coverage prerequisite failure.
Before reviewing image resources, trace the actual launch environment: its
configured caller fixture differs from immutable Source, while its .tmp and
coverage outputs are explicitly writable. Attribute physical owners using the
captured identities. The pinned Host-state two-file pilot reuses the existing
supervisor and leaves unsupported/stale selections serial; it does not permit
empty resource declarations or infer package-wide independence from one control.
If an interrupted checkout retains coverage custody, keep it intact and use a
clean same-commit checkout with matching SDK inputs for independent diagnostics.
Record both namespaces; never turn the old lock or UNKNOWN into a completed run.
Keep disk usage bounded through TESTING's terminal cache-retirement rule. Reuse
one same-input gitless image across compatible lanes using TESTING's
[execution contract](../../../packages/agent/TESTING.md#gitless-contour-execution),
and give read-only agents existing paths. Writers prepare bounded patches in ordinary
directories; do not create preparation worktrees. New Source does not refresh an old
image's evidence. Fence installs while shared dependencies have active producers.
Delete only verified
regenerable caches outside immutable checkouts after custody closes; keep original
failure evidence and all other retained scratch. Reuse the latest inventory.

## Design a regression

For a lease-race regression, distinguish an attempt's recorded `retry_lease`
from the Work's actual renewed lease. The Host reconciliation transaction and
the Journal-bound local renewal are different steps. A same-assignment retry
must already match its persisted retry fence before the approval resolver runs;
that retry alone cannot provide an intervening principal change. Check the
actual exported producer names and the completed native Work/lease afterimage
before preparing a race based on an assumed transition.

For a shared reference classifier, test the matching facts and vary each field
independently. Keep caller cardinality, revision and policy checks in their
original order. Lifecycle `current()` also filters `source_revision`, so it is
not interchangeable with a four-field approval classifier. Register a new
production helper in the selected contour's Source set; unit coverage of that
helper does not establish coverage of its callers' native refusal guards.
When that addition changes a recorded contour's Source set, retire the original
selection and register a successor name before measurement, as TESTING requires.
Keep the full tests and original frozen ceilings; never relabel a retained report
or relax the merger to accommodate a changed historical scope.

Pair overlapping-owner refusal with an active disjoint-owner control through
the fixture's existing public admission. Require nonempty ticket resources and
exact agreement with its active claim. Keep current
CAS after admission and exact peer Work/file preservation through success and
retry. An unstarted disjoint peer needs no extra bridge, synthesis or issued
workflow. Coverage of the visited predicates still needs the matching report.

When a regression specifically needs another Work's real Journal, an admitted
peer alone is insufficient. Check the producer's intake and live-owner contract
before launch: `preparePeerAdmission` omits intake by default. Declare the peer's
own raw intake before public admission, then use the actual configured ledger
and bridge to prepare a nonempty suspended first wave. Keep issue/observation
null and reservation absent under their actual schema, close its bridge before
repair, and preserve the peer's exact native rows and owner rights. This is
prepared foreign Work, not another attempt or provider execution.
The supported initial `start()` may prepare a Journal with null Source scope;
assert that exact state and stop before issue. Do not clear an already-bound
scope on resume. For mixed legacy/current repair, inspect after the controlled
Work alteration while the genuine Journal is still current, then continue the
existing both-legacy case. Capture governance/history before that first phase
so an inspection defect cannot become the later expected beforeimage.

Before removing an impossible canonical-equality comparison, retain any canonical
admission it performed on the transformed postimage. Added fields can cross a
node/byte limit even when the preimage fits. Reuse the existing value validator
when only validation is needed; unchanged-state and real migration controls
must still preserve raw CAS dependencies and issued/UNKNOWN semantics.

When repeated verifier reads protect a precommit freshness boundary, retain them.
Reuse the genuine fixture and change one owned input between the initial proof
and final recheck; assert the intended denial, exact restoration and unchanged
Host/Journal/receipt state. Preserve primary and restoration failures through the
existing cleanup owner. A repeated live check is not automatically duplicate work.
For repeated CAS denial oracles, typed exact native row beforeimages can avoid
repeated API decoding. Keep real API validation before/after the batch and after
success; preserve receipt, file-effect and unchanged-state checks for every denial.
Before comparing snapshots across Host, Ledger resume and recovery artifacts,
read their declared shapes. Compare exact version/state fields and assert each
API's own metadata separately: Host attempt and Ledger resume_status are different
wrapper fields, and the recovery artifact stores neither wrapper.
When a fixture already owns a configured ledger, expose that actual ledger and
its typed existing producer input for an additional proof. Do not reopen its DB
or repeat its engine setup. The original fixture retains close ownership; a
borrowed ledger is not a new handle to close. Prove initialized corrective
reservation settlement with the exact Journal and unchanged Host. This does not
cover start or any engine execution.
For a separate corrective-start proof, open the real configured bridge with its
persisted correctiveExecution and current source scope. Keep earlier claim and
retry oracles before that preparation. Stop at the suspended unissued wave,
check exact run/Journal agreement and terminal producer results, and close the
bridge through the async dual-error owner before the fixture closes its ledger.
Prepared requests do not prove provider execution or authorize effect replay.
For rollback failures, use distinct body/artifact/SQL sentinels, including thrown
undefined. Assert exact ordered error identities and original cause, persisted
rows/files, transaction state and later admissible entry. Keep an instance-local
driver spy distinct from native disk-failure proof; restore it and settle the
fixture-owned transaction before closing or deleting its root.

For YAML/configured-root fixtures, follow [TESTING's fixture contract](../../../packages/agent/TESTING.md#new-and-modified-files).
Use the bound config's registered and allowed projects; verify targeted negative
mutations actually occurred before testing rejection. Keep portable-template
and configured-root checks distinct from complete coverage qualification.
For mutation fixtures, prefer the sealed `AGENT_RUNTIME_TEST_CONTEXT_ROOT` over
the parent repository root. Keep parent Source/tool input resolution separate;
verify the fixture's exact bytes and layout through the existing runner owner.
For synthetic coverage fixtures, a tool input can also be maintained Source.
Use valid inert TypeScript for those bytes and preserve the untrusted marker.
Reuse the captured-module union owner for exact-path deduplication; keep category
digests and the independent alias checks intact.
Real runner fixtures await `prepareCoverageRunnerInputs` and its bounded runtime
closure capture. Do not maintain a second transitive import list. Keep explicit
computed-module seeds, which static imports cannot discover. Synthetic fixtures
derive declared Source/tool overlaps from their input owner. Configured-context
fixtures use a real `packages/agent` layout and the declared repository context
files; unrelated temporary directories cannot represent that admitted namespace.
For stateless import-time subjects, follow TESTING's body-local synchronous
fresh-loader method. Query spelling alone proves neither fresh identity nor ALS
attribution on Bun1.4.3. Verify the actual generated mutant, snapshot interception
and exact body-owned activation; a direct suite pass or static review is insufficient.
Reuse one typed test-local operation forwarder for a stateless subject invoked
from multiple bodies. Load the exact subject synchronously before the operation;
never rely on registration order or a different case's fresh load for attribution.
For opaque-capability modules, preserve their namespace and registry. TESTING's
immutable-string consumption tracking qualifies supported import-time constants
through their actual body-owned reads; never substitute a fresh module or dummy
utility call. Unsupported initialization evidence remains UNKNOWN.

Start from the contract and the function or boundary that owns it. Map each
plausible regression to a fixture, a concrete case, and an assertion at that
boundary. Use Zero, One, Many, Boundary, Interface, Exception and Simple. Add
Replay, Persistence and Cross-surface consistency where the contract needs
them. For stateful behavior, consider Fresh, Explicit, Persisted and Replay
modes. Explain why an inapplicable scenario does not apply. A category label,
placeholder or broad suite pass is not scenario evidence.

Prefer a focused unit check plus integration checks at supported CLI, SDK,
database and subprocess boundaries. Isolate fixtures and control external
dependencies. Keep persistence, restart, compare-and-swap, failure-before-effect
and UNKNOWN behavior real. Use deterministic property checks and independent
models where they protect the contract. A new test layer should cover a distinct

Keep typed error/state assertions and require fresh native proof; a5s timeout
against a5s production retry deadline cannot establish assertion-confirmed Killed.
The same observer can cover expiry only after the real pending probe and the
verified jump past the absolute deadline. At that point retry is forbidden;
observe both the binding await and its pending drain without releasing the
guard/quarantine. This does not prove mutations using another async mechanism.
The current function audit indexes literal test names and direct body assertions.
For a small scenario table, keep named wrappers with meaningful result assertions
and share the expensive scenario body. Mark fixture success after each wrapper's
assertions. Bun-valid interpolated registration alone does not establish audit
recognition; helper execution and static links remain different evidence.

For asynchronous case custody, enroll each root before the body can suspend.
Teardown must observe a pending body directly; a `finally` that marks failure
only after settlement is too late. Check the monotonic deadline again after
owned connection cleanup and before deletion. Use the runtime-config fixture's
case owner for its composite repair cases. Keep the same bound in that owner
and the Bun case. Qualify pending teardown with a real expected-timeout child,
preserving its failing child result and retained root separately from the
passing parent control.

For child programs, use Bun's `process.execPath`. For `-e`, pass named
environment values or serialize inert literals with `JSON.stringify`; do not
assume Node's positional argv layout. Observe stdout/stderr and native terminal
status. A signal request, missing PID or missing marker does not prove that a
child or descendant stopped. Arm a real timer before a readiness handshake when
the test depends on observing a deadline. Keep child, cleanup and parent limits
inside the owning case bound.

Use `tests/helpers/synchronous-child-outcome.ts`'s
`requireSynchronousChildSuccess` for isolated test-process health and completion
markers. Ordinary errors preserve the distinction between child infrastructure
failure and body assertion failure. A successful parent guard does not provide
the child's assertion causality or coverage counters.

Prepare public CLI child environments through the existing pinnedEnvironment
owner before launch, preserving explicit caller overrides. A raw environment
can make the entrypoint reload operation modules after cache-routing self-
reexecution. This preparation changes no authority or UNKNOWN predicate.

For callable CLI main tests, use its injected local exit recipient. Preserve
the exit-code assertion without mutating the Bun test process. Check native
command exit independently from the printed case counters.

An expected-UNKNOWN child control keeps its fixture retained after assertions
pass. Use the same cleanup owner as the real caller, with retention scoped to
the selected root and without resetting caller custody callbacks.
For request comparisons, derive expected values from independently seeded or
persisted fixture facts. Avoid invoking the production request builder again
as its own oracle. Keep versions and maintenance state explicit and never
reuse a test snapshot as production authority.

In copied snapshot fixtures, pass explicit `./` test paths so Bun does not
rediscover copied tests. Assert exact child file and case counts when fixture
cardinality matters. Keep fixture preparation separate from the case deadline.
Do not delete fixture state until assertions and owned checks succeed.

## Diagnose performance and parallel conflicts

Read executing-package bytes through `readRuntimePackageResourceBytes`; a
controlled beforeimage overlay delegates to `readRuntimePackageSourceResourceBytes`.
Direct SafeAccess `readBytes` can create CAS sidecars and fail on the immutable
execution image. Before the full contour run, check a new package-reading fixture
with the package mounted read-only and its caller context and scratch writable.
An immutable package and a mutable configured caller have different ownership;
making the caller config read-only can fail a global hook before the selected case.

When a Bun PASS row exceeds its declared case bound, follow TESTING's monotonic
setup/cleanup deadline rule. Check whether preparation throws before the body's
finally exists. Establish owned close handling before opening resources, preserve
setup and cleanup causes, and do not launch another phase after expiry.
When a shared controller constructor throws, fence later hooks and bodies with
the original failure instead of recreating it per describe block. An explicit
failure envelope preserves thrown undefined. Retain both raw child streams at
the uncertain-command boundary and bounded phase records inside owned scratch;
buffered stderr cannot explain a child killed before it returns. Use the existing
owned-cleanup helper to retain primary and diagnostic/close failures together.

Separate case timeout from protocol age thresholds. Compare identical complete
scopes under the same resource conditions. Record whole-command timing and
startup, collection, setup and child outcomes separately. Partial reporter rows
are not complete per-file timing weights. Do not infer speedup from operation
counts or instrumented wall time.
Verify the profiler artifact exists before attributing cost. The qualified Bun
test probe accepted --cpu-prof but emitted no profile. A bounded bun:jsc profile
started from a non-awaiting beforeAll and settled by afterAll captured the native
test stack; retain its raw stack data and distinguish sampled CPU from elapsed
time. A hot validation/canonicalization owner can justify a small equivalent
derivation change; verify exact bytes, dangerous data keys, descriptors and
rejection behavior before its native caller. Do not remove fresh runtime or
authority reads because their stacks repeat. Alternating micro comparisons with
overlapping ranges or warmup drift do not establish end-to-end speedup; overlapping
static checks likewise disqualify focused test times as performance comparisons.
When a profile identifies a scalar guard that allocates a single-condition
array per node, prefer its exact boolean expression. Preserve eager evaluation
for multi-condition guards and retain complete descriptor/Proxy/limit controls.
Check the owning contract suite before its native caller, then qualify the
changed input through the existing complete contour stage. A cheaper expression
or a faster focused observation alone does not close an earlier timeout.
Upgrade/activation/output presence probes use the existing observer without memoizing live
state; native controls must retain active-CAS denial and the unsupported-provider
fallback. Never replace writer CAS or durability with this read-path optimization.

For a repeated SQLite BUSY wait in a functional lease-denial case, use
[TESTING's native-denial control](../../../packages/agent/TESTING.md#process-timeout-and-fixture-safety).
Keep the real lock, exact connection, healthy retry and production timing policy;
do not replace the native denial with a thrown error.

For refusal before a write transaction opens, a private connection's query_only
mode can supply a native SQLITE_READONLY control. Qualify BEGIN IMMEDIATE on the
selected Bun/SQLite first. Preserve zero body/rollback calls, unchanged native
rows and artifacts, and no open transaction. Restore the observed original mode
through owned cleanup before the healthy control. This proves a pre-BEGIN denial,
not a BUSY lock, contention timing or persistence recovery.

For mutation resource pressure, distinguish disposable Bun `.pile` transpiler
cache from fixture/evidence data. Follow TESTING's isolated worker cache policy;
retain the exact cleanup manifest and every database, raw receipt and UNKNOWN
fixture. Cache deletion or disabling alone establishes no test/mutation result.

Check the actual mount backing a private fixture, including bind mounts. Use
TESTING's retained-host-tmpfs rule for disposable functional/process-recovery
cases; preserve all fsync calls and failed roots. This is not power-loss
durability evidence or parallel-coverage qualification.
Use the existing isolation owner's explicit `VIDA_QUALITY_RETAINED_SCRATCH_ROOT`
option for a qualified retained host root; it must already exist, be absolute
and resolve outside `packages/agent`. Keep its capacity/type receipt and unique
per-stage scratch. Never substitute a namespace-only ephemeral tmpfs or reuse a
failed root. Default storage and all timeout/evidence gates remain unchanged.

Classify real reader effects. An immutable `readFileSync` dependency and a
SafeAccess reader that creates compare-and-swap sidecars have different resource
behavior even when they share a path. A common parent directory alone does not
prove a conflict. Review transitive reads, writes, mocks, clocks, environment
and module order before changing resource tags. UUID leaves do not establish
whole-run independence.
For no-sidecar-creation controls, count `O_CREAT`, not every open of a CAS name;
verified observations probe retained lock names read-only. Qualify the observer
with an actual guarded-read positive control and keep native contention proofs.

Parallel coverage remains subject to the serial fallback and activation gates
in TESTING.md. A scheduler or native fixture pilot proves mechanics only. Do not
use partial receipts, child-local worker IDs, direct-child exit or released
measurement reservation as proof of descendant/effect quiescence or numeric
qualification. Preserve one final evidence owner and one checked global merge.

## Quick reference

| Need                    | Practice                                                                           |
| ----------------------- | ---------------------------------------------------------------------------------- |
| Regression              | Map contract, scenario and assertion to the owning boundary.                       |
| Focused check           | Explicit path and anchored name pattern; inspect the complete result.              |
| Fixture isolation       | Scope hooks, await work, restore mocks and retain failed roots.                    |
| Timeout                 | Separate per-test, parent, child, cleanup and report budgets.                      |
| Missing profile         | Check the capability with an inert control before an expensive case.               |
| Inventory or report     | Reuse maintained TypeScript tools; validate JSON before reading fields.            |
| Measurement reservation | Separate direct producer termination from measurement success and UNKNOWN effects. |
| Captured module query   | Preserve module identity and exact captured path; reject unbound requests.         |
| SDK artifact            | Bind emitted bytes and preserve production guards; ignore compiler name ordinals.  |

Run commands from `packages/agent` with the existing pinned launcher. Read the
package scripts for ordinary phase membership. Add each maintained test once
to its owner. The final-check owner alone collects coverage, CRAP and mutation
outputs.

Preserve a worker's declared base commit when integrating test repairs. Review
only its assigned diff, retain intervening canonical cases/helpers, and reject
unrelated deletions from an older full-file copy. A passing filtered run must
also identify actual executed cases; keep zero-match/skip-only selections
unsuccessful and separate from complete contour qualification.

## Priority boundary

P0 covers reproduced defects in existing contracts, blocking failures, security or data failures, and required delivery of their fixes. P1 simplifies or reduces work in supported behavior. P2 adds a capability, public contract, execution mode, engine behavior, adapter, or UI. Missing proof is a GAP, not a defect by itself. A real defect found during P1 or P2 work joins the current CLEAR scope. Preserve existing P2 prerequisites and boundaries in the backlog.

The eight P0 and ten P1 entries are work contours, not counts of confirmed bugs. Source implementation and final acceptance are distinct states. Historical `pending` labels do not override later evidence.
